# Screenshot-led UI consistency review

Scope: the supplied Budgets, Goals, Loans, net-worth overview/review and Home screenshots. Applied UI/UX Pro Max's verified empty-state, primary-action, readable hierarchy and time-series guidance, plus the Android adaptive skill within the existing Compose/navigation versions. No new font, chart library, storage schema or financial algorithm was introduced.

## Findings and implemented decisions

| Observed issue | Decision and user-workflow rationale |
| --- | --- |
| Bottom Back text, a circular Back control and a top-right Close vary between planning screens. | One shared top-left Back pattern reduces relearning and navigation search. Headers reflow at large text. |
| Goals repeats its first-goal action in the empty state and footer, beside an unnecessary zero summary. | One contextual creation action, with an inviting explanation of reserving rather than transferring money. Populated pages retain one footer add action. This reduces choice competition without hiding functionality. |
| A hollow-circle empty-state glyph resembles a stuck spinner. | Static, meaningful outline icons distinguish empty from loading and avoid false progress signals. |
| Budget battery fills compete with the amount and look like warnings even when within limits. | Neutral outlined cards, clear remaining/over-limit labels and slim proportional meters. Reordering, editing and adding remain available. Existing overall/category-limit information is retained; combined limits are explained rather than presented as extra spendable money. |
| Loans uses an unusually placed floating add control and a second bottom navigation-like bar. | Local labeled filters near the content, shared add actions, neutral loan cards and retained saved list position. |
| Net-worth review has a weak visual boundary, repetitive text links and actions below a long list. | Bounded neutral dialog, persistent Close and Save, whole-card choices, accessible full-row checkboxes and preserved review drafts. After editing an account, return to review to reduce repeated navigation. |
| Overview explanations form a long, visually ungrouped reading task. | Group completion/allocation information, use correct singular/plural wording, and disclose the unchanged repayment explanation on request. |
| Trend dots obscure the shape; legends/scales use inconsistent contrast and spacing. | Compare plain and shaded polylines, select subtle balance-only shading as the initial implementation, distinguish series with line patterns and semantic theme colors, show currency once and expose exact values on demand. No invented smoothing or history. |
| Spending bars are all effectively full width. | The presentation incorrectly clamps a percentage such as 43 directly into a 0–1 fraction. Divide by 100 before drawing; retain the original percentage and monetary calculations. |
| Hidden balances still expose chart geometry and spending proportions. | Remove scale, plot, values, percentages and bars from the hidden presentation rather than masking only the numeric total. |

The reasoning above is psychology-informed design judgment (choice reduction, grouping, progressive disclosure, recognition and truthful feedback), not a claim of measured user-study results. Retain Ivy's Raleway/Open Sans language and Jvy's neutral surfaces and purple/mint identity.

## Verification and review

Use fresh Paparazzi renders for 320dp/360dp phones, square folds, DeX, short landscape, 200% text and AMOLED. Cases include empty/populated states, long names, large amounts, budget overruns, overlapping overall/category limits, missing history, a single observation, negative balances and hidden values. Shared contrast tests include financial/chart text on neutral inset surfaces. The production net-worth dialog frame asserts Save remains inside every viewport with a 48dp target.

Run unit/render and financial regression checks without assembling an APK. Do not replace screenshot baselines until owner approval. Runtime TalkBack, keyboard, gesture-inset and device interaction checks remain device QA; static renders do not prove them.

Candidate previews are generated into the ignored `artifacts/ui-review/` directory after tests. Compare `trend-line-phone.png` and `trend-shaded-phone.png` (and their AMOLED counterparts); these contain synthetic fixture data, not the user's financial records. Implementation details belong in the [shared design language](JVY-DESIGN-LANGUAGE.md).

### Recorded results

- Final Gradle verification succeeded: 621 checks across nine affected/adjacent modules, including 260 rendered cases; zero failures, errors or skips. Domain and backup/repository regression checks were included.
- All eight review-frame cases assert a visible Save action within the viewport and a target height of at least 48dp.
- Exported 25 representative candidate PNGs, an offline gallery and a manifest to `artifacts/ui-review/2026-10-25/`; the complete review ZIP is `artifacts/ui-review/Jvy_UI_review_2026-10-25.zip`.
- Inspected fresh plain/shaded AMOLED trends, large-text chart labels, wide planning grids, and the persistent review controls. These are candidate visual checks, not owner baseline approval or hardware interaction tests.
- Existing APK `0.4.1` / `225` and its checksum are unchanged. No APK was built, signing identity changed, screenshot baseline replaced, or financial data migrated for this UI work.
