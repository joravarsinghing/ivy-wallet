# Goals and shared-theme audit — 26 October 2026

Scope: the owner's dark-mode Goals screenshots, creation/editing/reservations, shared foreground and date inputs, and regression checks across the existing app sections. This is a source/UI correction, not an APK release or a new financial model. Android adaptive and UI/UX Pro Max guidance informed the bounded layouts, clear validation and disclosure of unsupported currency conversions; no Compose/navigation upgrade was introduced.

Follow-up: this audit did not originally consolidate the pre-existing transaction and legacy date/time selectors. The owner identified that coherence gap. The [picker consolidation record](PICKER-CONSOLIDATION-2026-10-26.md) documents its correction; passing the earlier tests alone was not evidence of one shared picker implementation.

## Findings and corrections

| Finding | Cause | Correction |
| --- | --- | --- |
| Black headings on dark/AMOLED screens | `MaterialTheme` did not provide `LocalContentColor` for production non-legacy routes without a Surface. Preview-only surfaces concealed this. | Provide `onBackground` at the shared theme boundary; nested surfaces retain their own foreground. Make shared heading colors explicit. Render adaptive previews without an extra masking Surface and assert the theme contract. |
| Arbitrary deadline text saved as “No deadline” | Goals accepted free text but only parsed English month/year; parsing failures returned null. | Calendar-only optional input, typed `LocalDate`, exact UTC-day storage and localized display. Strictly reject invalid nonempty legacy labels. Preserve the old month-only meaning for legacy callers. |
| Awkward form, unequal choices and detached dismissal | Legacy modal controls, weighted text pseudo-buttons and large blank spacers. | Shared bounded form frame with a persistent Close, scrollable body and pinned submit/error area. Wrapping native chips, consistent shapes and type explanations. Add Edit to existing goals. |
| Phantom success and lost retry context | The page optimistically inserted a goal and closed before repository success. | Saveable drafts with stable IDs; wait for persistence. Keep failed drafts open with an announced error. Distinguish a failed save from a successful save whose subsequent refresh failed. |
| Incorrect currency label and silent reservation reduction | Creation hardcoded AED; reservation input was clipped to available funds. | Use the wallet currency. Reject invalid, nonfinite and over-available reservations with an explanation; compare available decimals without binary subtraction errors. Preserve existing allocations when editing. |
| Other-currency totals appear authoritative | Existing Goals storage has no currency field or reservation conversion. | Permit new reservations only from matching-currency accounts; preserve foreign/unavailable allocations unchanged and flag their totals for review in cards, details and reservation editing. Do not invent exchange rates or migrate the schema. |
| Material date selection can move back one day | UTC picker milliseconds were interpreted in the device time zone. | Shared UTC calendar conversion helpers, used by the shared date picker and new date field. Test western time zones, leap days and pre-epoch dates. |
| Small-screen calendar can exceed the window or clip day columns | Material 1.2's standard DatePickerDialog and day grid assume a wider surface. | Use seven proportional day columns inside the bounded frame, with locale-specific week starts, month/year navigation, full-date accessible button labels, selected/disabled semantics and pinned confirmation. Retain Material date state and selectable-date restrictions; test that every day appears exactly once. |

## Cross-section review

- Shared foreground correction covers Material3 routes, not just Goals. Explicit headings protect planning headers and empty states used in Goals, Budgets, Loans and import assistance. Nested button/surface foreground ownership remains intact.
- Wealth date fields reuse the typed picker and retain their existing future-date restrictions and ISO storage. Malformed values no longer masquerade as today's date. Transaction/planned-payment inputs use their existing selectors; no additional free-text deadline path was found.
- Audited direct black/white uses in the relevant features. Category contrast calculations and intentional foregrounds on colored legacy import controls are not blanket-replaced with page colors.
- Preserve the pending Home chart legend/finite-motion fixes, existing navigation ownership, biometric/PIN policy, hidden-balance behavior and financial formulas. No account/transaction/goal backup schema, database entity, package ID, key, version or APK workflow is changed.

## Remaining limits

- No emulator or connected phone is available here. Actual IME insets, TalkBack traversal, platform dialog stacking, hardware authentication/capture policy and resize interaction still need device QA; render tests do not certify them.
- Goal storage still has no per-goal currency. Changing the wallet currency can reinterpret existing targets; fully correct cross-currency goals need an explicit compatible data-model/conversion plan. This audit does not silently migrate data or claim that limitation is solved.
- A deadline already discarded by the old parser cannot be recovered. Edit the existing goal to select its intended day; do not fabricate it.
- Date values are localized; newly clarified English copy is not a claim of complete translation coverage.
- No screenshot goldens are replaced, and no APK is produced for this task.
